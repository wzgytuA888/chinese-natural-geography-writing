# 交稿核验与行为评估

用于完成稿件的内部检查或更新 skill 的独立演练。语言相似度、词频相似或程序通过不能证明期刊级论文质量；同行评价还涉及科学问题、设计、贡献与领域知识。

## 一票否决项

任一项出现即修改，不以语言流畅抵消：虚构数据/引文；单位或分母错误；百分比/百分点混淆；未检验却写显著；空间相关变成时间增长或现实因果；情景写成实测事实；重要性/q 误写物理贡献；无依据补造高值区、阈值、服务流或政策效果。

## 通过底线后检查六个维度

| 维度 | 合格表现 | 需要修改 |
|---|---|---|
| 证据可追溯 | 每个方向、数值与判断能回到输入 | 漂亮判断没有事实来源 |
| 研究问题回应 | 段首是有区分度的发现 | 仅复述表格或背景 |
| 结构完整 | 概括、证据、对照/例外依次推进 | 模板要求了未提供的维度 |
| 推论有界 | 输出本义、尺度和情景明确 | 相关、机制和政策效果混写 |
| 表达清楚 | 主语和指代可辨，指标搭配准确 | 套话、过长修饰、术语轮换 |
| 信息节制 | 数值支持中心发现，异常保留 | 所有数值平均堆入正文 |

可按 0（错误/缺失）、1（部分做到）、2（完整做到）记录内部评分。评分帮助定位修改，不是录用概率或人工专家分数；有任一否决项时总分无效。

## 独立演练

使用 [../evals/cases.json](../evals/cases.json) 中的原创数据。将 skill 和每例的 `input` 给评估者，隐藏 `checks`、参考段落和修改者判断。要求评估者实际生成段落，再由另一检查者依据输入核查；不能只询问是否理解规则。

对比旧版与新版时保持输入、模型和任务范围一致，记录生成文本、事实错误及缺失条件。不以阅读 skill 后填写“规则齐全”替代行为结果。不做基于单次案例的普遍质量保证。

## 交付形式

默认只交付用户所需正文。若存在会改变结论的证据缺口，另用短句注明；用户要求质量审计时再提供核对表和评分。润色任务保留事实、引用编号和技术含义，不擅自新增分析。
